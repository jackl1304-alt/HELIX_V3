## 5. Architektur-Entscheidungen (für morgen als Kontext)

### 5.1 Source-Flag-System
| Flag | Bedeutung | Beispiel |
|---|---|---|
| ✅ | Direkt verifiziert via `read_url` | `https://www.fda.gov/.../QMSR-Final-Rule` |
| 🟡 | Sekundärquelle / Aggregator / ISO-403-Paywall | `https://www.iso.org/standard/72314.html` |
| ⚪ | „Representative" / noch zu verifizieren | Patente ohne Status-Verify |

### 5.2 i18n-Pattern (Pass 5 etabliert)
- **Library:** Eigener `LanguageContext` (kein i18next), Keys als String-Lookup mit `t('key')` als Fallback auf Key
- **Locale-Persistence:** `localStorage['helix-language']`
- **HTML-Lang-Attribut:** wird automatisch via `document.documentElement.lang = language` gesetzt
- **Konsistenz:** Jeder neue String MUSS in DE + EN in `LanguageContext.tsx` ergänzt werden
- **Header-Sync:** Language-Select in Header ist jetzt an Context angebunden, alle 4 Sidebars reagieren synchron

### 5.3 Sidebar-Struktur (Pass 5 etabliert)
- 6 Sektionen in fester Reihenfolge (kundenorientiert: Overview → Compliance → Approvals → Projects → Standards → Advanced)
- Sub-Items per Chevron auf-/zuklappbar, Default-Status pro Sektion konfigurierbar
- Premium-Badges (👑) für Admin-only Items
- Live/Neu/AI-Badges für neue Features
